UX Design Specification — Genie

Author: Teddy Date: 2026-03-16

Executive Summary​

Project Vision​

Genie là AI-powered Chrome Extension đưa AI assistance trực tiếp vào browser workflow của CyberAgent employees — không cần rời khỏi trang đang đọc. Mọi AI request được proxy qua genie-api nội bộ, đảm bảo data không rời CyberAgent infrastructure. Design language: Linear-inspired — dark, minimal, fast, polished.

Core design philosophy: confidence-first, không phải speed-first. Genie giải quyết anxiety của người dùng trước, tốc độ là hệ quả tự nhiên — không phải mục tiêu chính.

Target Users​

Linh / Comtor (Primary): Dịch technical spec JP↔VI/EN. Core fear: submit sai mà không biết. Emotional core — cô ấy không sợ chậm, cô ấy sợ bị sai. Cần confidence + source citation để dám submit — Genie giải quyết anxiety, không chỉ tốc độ.

Minh / Developer: Tìm thông tin trong Confluence docs dài. Skeptical với AI — chỉ trust nếu có citation cụ thể từ nguồn. Trust requirement: "Thông tin này từ [System Architecture v2, mục 4.3]" mới đủ để hành động.

Hana / Office Staff: Xử lý báo cáo và announcements đa ngôn ngữ. Hiện dùng ChatGPT như workaround hàng ngày — biết là rủi ro nhưng không có lựa chọn. Cần tốc độ và không rời trang.

Key Design Challenges​

  1. Trust UI — Confidence indicator + source citation phải cực kỳ rõ ràng để Comtor và Developer dám tin vào output và hành động ngay. Đây là centerpiece của toàn bộ UI, không phải feature phụ.
  2. Non-intrusive sidebar injection — Sidebar phải hoạt động trên bất kỳ trang nào (Shadow DOM) mà không phá vỡ layout của host page — đặc biệt Confluence, Slack, Jira.
  3. Progressive disclosure cho 3 personas — Một UI, ba levels of depth: default view đủ simple cho Hana, expand để thấy citation detail cho Minh, confidence indicator luôn visible cho Linh.
  4. Feedback loop UX — v1 bao gồm inline accept/reject feedback (FR38). Interaction design cho feedback phải đủ lightweight để không interrupt workflow nhưng đủ explicit để capture useful signal cho knowledge layer.
  5. Graceful degradation UX — Khi không có Confluence context hoặc offline, UX phải communicate rõ ràng — không silently degrade.

Design Opportunities​

  1. Confidence as visual signature — Confidence indicator ●●●●○ có thể trở thành visual identity của Genie — unique, memorable, và trực tiếp giải quyết Comtor's core anxiety. Không AI tool nào đang làm điều này tốt.
  2. Contextual text-selection trigger — Genie có thể gently suggest "Translate?" ngay tại điểm selection — zero friction path to first value, không cần user mở sidebar trước.
  3. Engineered aha moment — Onboarding flow thiết kế để deliver aha moment ngay lần đầu: select text → translate → thấy Confluence citation → trust established.
  4. "AI đọc cùng bạn" positioning — Genie không chờ user hỏi, Genie nhìn những gì user đang đọc và proactively surfaces insights. Mental model này không thể bị ChatGPT copy vì họ không biết user đang đọc gì — đây là true differentiation.

Core User Experience​

Defining Experience​

Core loop của Genie: Select text → Get grounded answer with confidence signal. Interaction này xảy ra hàng chục lần mỗi ngày với primary persona (Comtor). Mọi UX decision đều phục vụ việc làm core loop này nhanh, trustworthy, và effortless.

Platform Strategy​

  • Platform: Chrome Extension (Manifest V3), Shadow DOM sidebar — desktop only, v1
  • Input modality: Mouse/keyboard primary; text selection là entry point chính
  • Always-on presence: Extension available trên mọi trang; sidebar toggle on demand
  • Offline handling: Graceful degradation — sidebar visible nhưng actions disabled kèm status message rõ ràng

Effortless Interactions​

  • Text selection tự động trigger contextual action tooltip — zero steps to first action
  • 1-click to translate/summarize từ tooltip hoặc sidebar
  • Confidence indicator readable ngay lập tức — không cần tooltip hay decode
  • Source citation dẫn thẳng đến Confluence page trong 1 click

Critical Success Moments​

  1. First Confluence citation — Response đầu tiên có citation = aha moment = trust established
  2. Low-confidence warning comprehension — ●○○○○ phải được đọc đúng và hành động đúng ngay lần đầu
  3. Guided first-use — Onboarding flow engineering để deliver first value trong < 2 phút

Experience Principles​

  1. Confidence first — Mọi AI response phải có tín hiệu tin cậy rõ ràng trước khi user đọc nội dung
  2. Zero-step entry — Text selection là đủ để trigger Genie — không cần mở sidebar, không cần extra click
  3. Progressive depth — Default view đơn giản cho Hana; expand để thấy citation detail cho Minh; confidence always-visible cho Linh
  4. Honest uncertainty — Khi không có context, Genie nói thẳng và suggest verification — không hallucinate với vẻ confident

Desired Emotional Response​

Primary Emotional Goals​

Primary: Calm confidence — "Tôi biết mình đúng và không cần ai xác nhận lại." Genie không thiết kế để gây excitement hay delight. Target user đang lo lắng — Genie giải quyết anxiety trước, speed là hệ quả tự nhiên.

Secondary: Relief — cảm giác "vấn đề đã được giải quyết, tôi có thể tiếp tục."

For Developer persona: Trust — "Thông tin này đến từ nguồn thật, tôi có thể hành động."

Emotional Journey Mapping​

Micro-Emotions​

  • Confidence over Speed — users want to be certain, not just fast
  • Trust over Delight — Minh (Developer) needs to trust before he likes
  • Informed over Frustrated — when errors occur, users must know why and what next

Emotions to actively avoid:

  • False confidence — Genie appearing confident when context is weak → most dangerous failure mode
  • Surprise confusion — UI behaving unexpectedly on unfamiliar pages
  • Abandonment anxiety — feeling stuck when genie-api is offline

Design Implications​

  • Calm confidence → Confidence indicator is always visible, never hidden. Uses calm visual language (dots, not alarming colors) that communicates gradation.
  • Trust → Source citations are first-class UI elements, not collapsed/secondary. Developer must see citation before reading the answer.
  • Informed uncertainty → Low-confidence state is a distinct, explicit UI mode with clear explanation and actionable next step — not just greyed-out text.
  • Informed error → Offline/error states show friendly, specific messages with retry — never blank or crashed UI.
  • Calm during wait → Streaming response (visible progress) prevents anxiety during the 2s response window.

Emotional Design Principles​

  1. Anxiety reduction over delight — every design decision should first ask: does this reduce user anxiety?
  2. Honest signals, always visible — confidence and source are never hidden or secondary; they are the response
  3. Graceful honesty — when Genie doesn't know, it says so clearly and kindly — never pretends
  4. Predictable presence — sidebar appears and behaves consistently on every page; no surprises

UX Pattern Analysis & Inspiration​

Inspiring Products Analysis​

Linear (design language reference): Dark minimal, generous spacing, every element has purpose. Cmd+K command palette as zero-friction entry point. Monochrome with accent only for attention.

Raycast (overlay paradigm): Contextual UI within current page, no flow interruption. Selection-triggered action overlay — suggest actions at the point of selection, not requiring sidebar scroll. Progressive result streaming.

Perplexity AI (AI + citations): Inline citations [1][2] embedded in response text, not footer. Sources visible while reading, not requiring scroll to verify. Source count as confidence proxy.

Transferable UX Patterns​

Entry Patterns:

  • Cmd+K keyboard shortcut to open/focus sidebar — zero-friction, no mouse required
  • Selection tooltip — mini action menu near selected text before full sidebar open

Response Patterns:

  • Inline citations [1][2] within response text — first-class elements, not collapsed list
  • Streaming token-by-token — visible progress prevents "broken" perception during 2s wait
  • Source count summary ("3 internal sources") displayed before response body

Confidence Patterns:

  • Dot indicator ●●●●○ — readable instantly, no decoding required; calm visual language
  • Distinct low-confidence UI mode with explicit message and actionable next step

State Patterns:

  • Inline status banner (top of sidebar) for offline/error — does not takeover; shows context

Anti-Patterns to Avoid​

  • Modal dialogs — full-page interruption destroys in-page workflow
  • Hidden confidence — confidence in tooltips only = not serving its purpose; must always be visible
  • Collapsed citations by default — "See sources ▾" requires extra click Minh won't take → no trust
  • No visible streaming — blank screen for 2+ seconds feels broken even if response is coming
  • Generic error messages — "Something went wrong" insufficient; must specify: server vs Confluence vs auth
  • Extension badge notifications — distracting in enterprise context; Genie is passive until triggered

Design Inspiration Strategy​

Adopt directly:

  • Linear's visual language: dark, minimal, monochrome base, accent for attention only
  • Perplexity's inline citation pattern: [1][2] in-text, visible without interaction
  • Raycast's selection overlay: contextual mini-menu at selection point

Adapt for Genie:

  • Raycast's progressive streaming → adapt with Confluence source count header before response body
  • Perplexity's source list → simplify to Confluence page title + section link (internal only)

Genie-original (do not copy from anywhere):

  • ●●●●○ confidence dot indicator as primary trust signal — this is Genie's visual signature
  • Explicit low-confidence mode with "Không tìm thấy context nội bộ" message and verification CTA

Design System Foundation​

Design System Choice​

Selected: Tailwind CSS + shadcn/ui (Themeable System approach)

Theme direction: Linear-inspired — dark background (#0a0a0a range), minimal color palette, monochrome base with single accent color for interactive elements.

Rationale for Selection​

  1. Shadow DOM compatible — Tailwind utility classes inject cleanly into Shadow DOM without CSS bleeding to/from host page; shadcn/ui components are owned code, not external package
  2. Linear aesthetic achievable — shadcn/ui dark theme + Tailwind customization reaches Linear-level visual quality without building component library from scratch
  3. AI-agent optimized — shadcn/ui is code you own; AI coding agents can read, modify, and extend components directly — no black-box library
  4. Polished defaults — animation, accessibility, keyboard navigation built into components; solo developer does not implement these manually
  5. Custom component flexibility — confidence indicator dots (●●●●○), selection tooltip, inline citation markers are fully custom; shadcn/ui does not constrain these

Implementation Approach​

  • Base: shadcn/ui component set as starting point (Button, Input, Tooltip, Scroll Area, Badge)
  • Theme: Custom Tailwind config with Linear-inspired color tokens
  • Shadow DOM injection: Tailwind CSS built and injected via content_script into Shadow DOM
  • Custom components: Confidence indicator, selection tooltip, citation marker — built from scratch using Tailwind primitives, not adapted from library

Customization Strategy​

Design tokens to define:

  • Background: near-black (#0d0d0d sidebar, #111 response area)
  • Text: primary white (#f5f5f5), secondary muted (#888)
  • Accent: single brand color for interactive elements (TBD — blue or violet range)
  • Confidence dots: filled (●) vs empty (○) using accent and muted colors
  • Border: subtle (#222) — separates sections without visual weight

Components to adopt from shadcn/ui: Button, Input, ScrollArea, Tooltip, Badge, Separator

Components to build custom: ConfidenceIndicator, SelectionTooltip, CitationMarker, StreamingResponse, OfflineBanner, OnboardingOverlay

Defining Core Experience​

Defining Experience​

"Highlight to understand" — select bất kỳ text nào, nhận ngay context từ trong tổ chức của bạn, với tín hiệu tin cậy rõ ràng.

Core loop: text selection → SelectionTooltip → action → confidence-first response

If we nail this single interaction, everything else follows.

User Mental Model​

Current behavior: Copy → new tab → paste to ChatGPT → read → return → apply. 5-6 steps, full context switch, security anxiety.

Mental model users bring: "Copy-paste to AI tool" — they hate it but know how. Genie meets them there, then eliminates the context switch entirely.

What Genie breaks (positively): AI always sounds confident. Genie tells the truth about confidence level — users learn this is a feature, not a limitation.

Familiar anchors for novel patterns:

  • Confidence dots ≈ mobile signal bars — more = better, instantly understood
  • Low-confidence mode ≈ "draft" indicator — Genie gives you a working draft, flag to verify

Success Criteria​

  1. ≤ 2 steps from text selection to action fired — no sidebar navigation required
  2. First streaming token visible in < 2s from action trigger
  3. Confidence indicator readable in < 1s — no cognitive decoding required
  4. Citation opens Confluence source in 1 click — no search required
  5. Comtor submits work without requesting dev confirmation — ultimate behavioral metric

Novel UX Patterns​

Established (no education needed):

  • Text selection as entry point — native browser behavior
  • Sidebar panel — familiar from browser tools, Notion, etc.
  • Inline citations [1][2] — familiar from Wikipedia, Perplexity

Novel (require brief onboarding education):

  • Confidence indicator ●●●●○ — not a standard pattern; needs one-time explanation
  • AI explicitly signaling uncertainty — counter to user expectations; needs framing as feature

Experience Mechanics​

Initiation:

  • Text selection on any page → SelectionTooltip appears near selection with [Translate] [Summarize] [Ask]
  • Alternative: Cmd+K → focus sidebar input directly (sidebar opens if closed)

Interaction:

  • Click action → sidebar opens, loading state shows immediately
  • Target language pre-selected from last session (no re-selection needed)
  • Streaming begins: confidence indicator + source count appears first, then response text

Feedback:

  • Confidence indicator and "N internal sources" render before response body
  • Response text streams with inline citations [1][2]
  • Accept/Reject feedback buttons appear after response completes — non-blocking

Completion:

  • User reads response + optionally clicks citation to verify in Confluence
  • [Accept] logs positive feedback signal; subtle animation confirms
  • Sidebar stays open, cleared for next action — no restart required

Design Direction Decision​

Design Directions Explored​

Three directions were generated and evaluated (see ux-design-directions.html for interactive mockups):

DirectionConceptConfidence TreatmentEntry Point
A — Confidence FirstStructured toolbar + prominent confidence blockFull block above responseAction toolbar
B — Command MinimalUltra-minimal chrome, Cmd+K firstBar-style meta lineCommand palette
C — Conversational CardsChat-bubble layout, self-contained cardsCard header per responseChat input

Chosen Direction​

Primary: Direction A — Confidence First

Adopted element from Direction C: Low-confidence card as a distinct amber UI mode (not just a subtle indicator change)

Design Rationale​

  1. Confidence block leads — Direction A's prominence of the confidence signal before response text directly serves Linh's anxiety reduction goal. This is the most critical UX decision in the product.
  2. Action toolbar discoverable — New comtor users immediately understand what Genie can do. Direction B's command-first approach requires learning; too high a bar for pilot onboarding.
  3. Direction C's low-confidence pattern is the clearest expression of graceful degradation across all three — the amber card with explicit warning message is visually unmissable. Adopt this pattern into Direction A for low-confidence states.
  4. Sidebar panel vs. chat layout — Direction A keeps conversation secondary and AI action primary; aligns with task-completion mental model of enterprise users rather than open-ended conversation.

Implementation Approach​

Sidebar structure (top to bottom):

  1. Header — Genie logo + connection status
  2. Action toolbar — Translate / Summarize / Next Steps / Ask (always visible)
  3. Response area — confidence block → response card → citations → feedback
  4. Input row — follow-up question field + send

Low-confidence state (from Direction C):

  • Replace confidence block with amber-tinted card header
  • Inline warning message: "Không tìm thấy context nội bộ. Bản dịch dựa trên general knowledge — nên verify với technical owner."
  • Dots change to amber ●○○○○ color scheme

AC — Session Expiry Auto-Retry:

Given user's SSO session expires while sidebar is open, When any AI action is triggered, Then sidebar displays inline auth banner (response area remains visible), SSO re-auth via popup (no page navigation), and pending action retries automatically after successful re-auth — user does not need to re-submit.

Journey Patterns​

Entry Patterns:

  • Selection → Tooltip → Action (zero sidebar interaction — lowest friction)
  • Cmd+K → Direct input (power user, keyboard-first)
  • Toolbar button click (explicit, discoverable for new users)

Confidence Patterns:

  • High: neutral card, blue dots ●●●●○, confidence block before response text
  • Low: amber card, amber dots ●○○○○, warning message before response
  • No sources: same as low confidence + "Không tìm thấy context nội bộ" explicit message

Feedback Patterns:

  • Accept/Reject always non-blocking — appears after response complete, never interrupts reading
  • Accept: silent success animation + feedback logged
  • Reject: silent log, input focused for optional follow-up

Error Recovery Patterns:

  • genie-api offline → OfflineBanner top of sidebar, actions disabled, retry on reconnect
  • Auth expired → Inline slim banner, popup re-auth, auto-retry pending action
  • Confluence index unavailable → Low-confidence mode with specific Confluence message

Flow Optimization Principles​

  1. Zero re-work on error — every error state auto-retries or preserves context; users never lose work
  2. Language preference persists — one selection, remembered forever; repeat users have zero overhead
  3. Onboarding guarantees aha moment — redirect to Confluence page if needed; don't let luck decide first impression
  4. Session expiry is invisible to workflow — inline banner + auto-retry means Linh never notices the session expired

Custom Components​

ConfidenceIndicator​

Purpose: Communicate AI response reliability before user reads content — centerpiece of trust UI.

Anatomy: 5 dots (●●●●○) + confidence label + source count

States:

  • high (4-5 dots): blue dots (#5E6AD2), "High confidence", neutral card background
  • medium (3 dots): blue dots, "Medium confidence", neutral background
  • low (1-2 dots): amber dots (#F59E0B), "Low confidence", amber-tinted background (#1a1200)
  • none (0 dots): amber dots, "No internal context", amber-tinted background

Accessibility: aria-label="Confidence: 4 out of 5. 3 internal sources." — screen reader text alongside visual dots.

SelectionTooltip​

Purpose: Zero-friction action trigger at the point of text selection — eliminates need to open sidebar first.

Anatomy: Floating card with 3 action buttons [Translate] [Summarize] [Ask], positioned above/below selection midpoint.

States: visible (on mouseup with text selected), hidden (click outside or action triggered)

Behavior: Appears within 300ms of mouseup; dismisses on Escape or click outside; auto-repositions if near viewport edge.

Accessibility: role="toolbar", keyboard navigable with Arrow keys, Enter to activate focused button.

CitationChip​

Purpose: Inline source reference that lets users verify Confluence sources in one click.

Anatomy: ↗ icon + Confluence page title (truncated at 30 chars with full title in tooltip).

States: default (accent bg #1a1e3d), hover (brighter), visited (muted color)

Behavior: Opens Confluence URL in new tab (target="_blank" rel="noopener").

Accessibility: aria-label="Source: [full page title]".

StreamingResponse​

Purpose: Response container supporting progressive token-by-token text rendering.

Anatomy: Text content area with animated cursor while streaming; CitationChips render inline as encountered in stream.

States: streaming (cursor blinking, text appending), complete (cursor hidden, feedback buttons appear)

Behavior: ConfidenceIndicator renders and is fully visible before streaming text begins.

OfflineBanner + AuthBanner​

Shared anatomy: Slim banner (40px height) pinned to top of sidebar — icon + message + CTA button. Neither banner hides previous response content.

  • OfflineBanner: Muted gray — "Không thể kết nối đến Genie · [Retry]"
  • AuthBanner: Amber (#1a1200 bg) — "Phiên làm việc đã hết hạn · [Đăng nhập lại]"

LowConfidenceCard​

Purpose: Distinct amber-styled response container for low/no-confidence states — visually unmissable.

Anatomy: Amber card header (ConfidenceIndicator in amber state) + warning message block + response text below.

Warning message: "Không tìm thấy context nội bộ. Bản dịch dựa trên general knowledge — nên verify với technical owner."

OnboardingOverlay​

Purpose: 3-step first-use wizard covering SSO connect, feature tour, and guided demo.

Anatomy: Full-sidebar overlay with step progress indicator (1/3, 2/3, 3/3), content area, and primary CTA.

Steps: (1) SSO connect → (2) Feature tour with toolbar highlights → (3) Guided demo on Confluence page.

Behavior: If user is not on a Confluence page at Step 3, prompts navigation to Confluence before demo.

Component Implementation Strategy​

  • All custom components use Tailwind CSS utility classes with project design tokens
  • Custom components inject cleanly into Shadow DOM (no external CSS dependencies)
  • shadcn/ui components are owned code — AI coding agents can read and modify directly
  • Shared design tokens (--accent, --bg-surface, etc.) ensure visual consistency across all components

Implementation Roadmap​

Phase 1 — Core (required for functional demo):

  1. ConfidenceIndicator — centerpiece of trust UI; nothing works without this
  2. StreamingResponse — required for core translation loop
  3. CitationChip — required for Developer trust requirement
  4. LowConfidenceCard — required for graceful degradation

Phase 2 — Entry points and error states: 5. SelectionTooltip — zero-friction entry; without this users must open sidebar manually 6. OfflineBanner + AuthBanner — error and session states

Phase 3 — Onboarding: 7. OnboardingOverlay — 3-step wizard; can ship pilot with simplified version initially

UX Consistency Patterns​

Button Hierarchy​

Toolbar actions (Translate / Summarize / Next Steps / Ask):

  • Equal visual weight — all peer-level; no primary/secondary distinction
  • active state: accent-tinted background while action in progress
  • disabled state: muted color, no hover, when sidebar offline

Response actions:

  • Accept: positive secondary — green-tinted border (border-color: #1a3a2a, color: #4ade80) — never filled
  • Reject: neutral secondary — default border (#222), muted text
  • Retry: accent border — draws attention in error recovery
  • Rule: never use solid/filled buttons in response area — only border buttons to avoid competing with content

Only 1 solid button at any time: the Send (↑) button in the input row.

Feedback Patterns​

StateTreatmentDismissible?
Success (Accept)Brief checkmark animation on button, silentAuto-dismisses
Warning (Low confidence)Amber LowConfidenceCard — persistentNo — user must read and scroll past
Error (Offline)OfflineBanner slim at topNo — until connection restored
Error (Auth expired)AuthBanner amber slim at topNo — until re-auth complete
InfoMuted text label (timestamp, model, freshness)N/A — passive

Rule: No toast notifications. All feedback is inline within the sidebar — never floating overlays that obscure page content.

Loading States​

  • Action triggered: Confidence block with skeleton dots renders immediately; text streams after
  • Extension init: Logo + subtle spinner — sidebar visible, content loading
  • Citation resolution: Chip title renders immediately; Confluence link resolves async in background

Rule: Never blank screen. Skeleton state must appear within 100ms of action trigger.

Empty States​

ContextTreatment
First open, not onboardedOnboardingOverlay — no empty sidebar shown
First open, onboarded, no sessionPrompt: "Select text on this page, or press Cmd+K to ask anything"
Confluence no resultsLowConfidenceCard (not a traditional empty state — Genie always responds)

Navigation Patterns​

Sidebar is single-panel — no nested navigation in v1.

  • Scroll within response area for long responses (ScrollArea component)
  • No back button, no breadcrumbs — linear interaction model
  • Toolbar always visible at top — context never lost

Interaction Micro-patterns​

  • Hover states: All interactive elements show hover within 100ms — background: --bg-elevated or border-color shift
  • Focus rings: 2px accent outline, 2px offset — visible on all keyboard-navigable elements
  • Animation timing: 150ms ease-out for state transitions; 300ms for overlay appear/disappear
  • Cursor: pointer on all clickable elements — no ambiguity

Responsive Design & Accessibility​

Responsive Strategy​

Platform scope: Desktop-only, Chrome browser (v1). Mobile deferred to v3+.

Sidebar layout across desktop sizes:

  • Fixed width: 380px — does not change with screen width
  • Height: 100dvh — full viewport height; response area scrollable inside
  • Sticky: toolbar (top) + input row (bottom) — always accessible regardless of scroll position
  • Minimum tested viewport: 1366×768 (common enterprise laptop in Vietnam)
  • At 1366px: sidebar occupies ~28% of screen width — host page content visible at 72%

Browser zoom: All sizing in rem — scales correctly at 100%, 110%, 125% zoom.

Breakpoint Strategy​

No traditional breakpoints — single-platform (desktop Chrome).

Within sidebar, content adapts to viewport height:

  • >= 768px height: Full layout — toolbar, response area, input row all visible
  • < 768px height: Response area height contracts; toolbar and input row remain sticky

Accessibility Strategy​

Target compliance: WCAG 2.1 Level AA

RequirementImplementation
Color contrast (4.5:1 AA)Primary text on base: 18.1:1 — exceeds AAA
Focus indicators2px accent (#5E6AD2) outline, 2px offset on all interactive elements
Not color-alone for statusError/warning: color + icon always paired
Screen reader supportaria-label on ConfidenceIndicator; aria-live="polite" on StreamingResponse
Keyboard navigationFull Tab order through toolbar → input → actions
Minimum click targetsButtons: 32px height minimum; Send button: 36px

Keyboard navigation map:

  • Tab — toolbar buttons → input field → response actions
  • Enter / Space — activate focused button
  • Escape — dismiss SelectionTooltip
  • Cmd+K — open/focus sidebar from any page context
  • Arrow keys — navigate SelectionTooltip action buttons

Testing Strategy​

Responsive: Viewports 1366×768 and 1920×1080; zoom 100%, 110%, 125%; Chrome stable only.

Accessibility:

  • Automated: axe DevTools scan on each component during development
  • Keyboard-only: Tab through full sidebar workflow without mouse
  • Screen reader: macOS VoiceOver smoke test on ConfidenceIndicator, CitationChip, AuthBanner, LowConfidenceCard
  • Contrast: Chrome DevTools accessibility panel for all color pairs

Implementation Guidelines​

Responsive:

  • rem for all font sizes and spacing — never fixed px for user-facing sizes
  • height: 100dvh for sidebar (dynamic viewport height)
  • Response ScrollArea: overflow-y: auto within fixed sidebar height

Accessibility:

  • Semantic HTML: <nav> for toolbar, <main> for response area, <footer> for input row
  • All icon-only buttons have aria-label
  • aria-live="polite" on StreamingResponse — announces new content without interrupting
  • aria-disabled="true" on toolbar buttons when offline (not disabled — preserves Tab focus)
  • SelectionTooltip: role="toolbar", aria-label="Genie actions", manages own focus trap
