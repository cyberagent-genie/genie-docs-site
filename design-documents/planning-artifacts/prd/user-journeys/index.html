User Journeys

Journey 1: Comtor — Happy Path​

Persona: Minh — Comtor, 3 years experience

Minh receives a 15-page Japanese spec with microservice architecture terminology. Deadline: this afternoon for dev kickoff.

Opening Scene: Minh opens the spec on Confluence, encounters "idempotency key" — unknown how to translate in this technical context. Previous approach: Google, ask dev, wait. 15 minutes per term.

Rising Action: Minh opens Genie sidebar (Cmd+K), selects the paragraph containing the term, clicks Translate → Vietnamese. Genie cross-references CyberAgent's Confluence, finds an internal design doc explaining the concept in context of the current system.

Climax: Genie responds in < 2s:

  • Translation: "Khóa bảo đảm tính nguyên tử của request"
  • Confidence: ●●●●○ (High — based on 3 internal docs)
  • Source: [Link to internal design doc]

Minh reads the source, understands immediately — no dev consultation needed.

Resolution: Minh completes 15 pages in 2 hours instead of a full day. Dev team kickoff runs on schedule. Zero misunderstandings in the sprint.

Capabilities: Text selection → translate, Confluence RAG lookup, confidence indicator, source citation, streaming response.

Journey 2: Comtor — Edge Case (No Internal Context)​

Persona: Minh — same day, different task

Minh encounters a new architectural pattern the company has never used. No internal docs exist.

Rising Action: Genie finds no match in Confluence index. Instead of silently providing a confident but wrong answer, Genie returns:

  • Confidence: ●○○○○ (Low — no internal context found)
  • Translation based on general LLM knowledge
  • Warning: "Không tìm thấy context nội bộ. Bản dịch dựa trên general knowledge — nên verify với technical owner."

Resolution: Minh sees the warning, sends a quick message to dev to confirm. Workflow unblocked — Minh has a working draft and only needs to verify one point. No time wasted on manual research from scratch.

Capabilities: Graceful degradation, low-confidence warning, no hallucination under uncertainty, actionable UX signal.

Journey 3: Developer — Confluence Search​

Persona: Kenji — Backend Developer

Kenji needs to understand the SSO token refresh flow for a new API endpoint. Confluence search returns 47 results.

Rising Action: Kenji opens Genie, asks in English: "How does our SSO token refresh work with the legacy API?" Genie synthesizes from 3-4 docs, returns a structured answer with sequence steps, direct quotes, source links, and a freshness note: "Page X is outdated from March — Page Y is the current version."

Resolution: Kenji implements correctly on first attempt. Saves 1-2 hours of research.

Capabilities: Natural language Q&A over Confluence, multi-doc synthesis, source citation, recency signal, multilingual input.

Journey 4: IT Admin — Setup & Configuration​

Persona: Hiroshi — IT Operations

Hiroshi receives the task to deploy Genie for the 4-comtor pilot.

Steps:

  1. Deploy Chrome Extension to 4 comtor machines via enterprise Chrome policy
  2. Configure genie-api: Confluence OAuth credentials, select indexed spaces
  3. Set AI model whitelist: GPT-4o + Claude 3.5 Sonnet
  4. Trigger full Confluence index (one-time)
  5. Verify SSO connection with company Identity Provider

Resolution: Pilot goes live. Daily incremental sync runs automatically. genie-api logs surface any errors for debugging without manual monitoring.

Capabilities: Enterprise Chrome deployment, Confluence OAuth + space selection, model allowlist config, full index + daily sync, SSO integration, operational logging.

Journey 5: CTO — Pilot Review & Go/No-Go​

Persona: Tanaka-san — CTO

After 6 months, Teddy compiles pilot data for org-wide deployment decision.

Data presented: Return Rate 75% weekly retention (month 2), Session Duration avg 12 min, NPS 8.2/10 with comment "I'm no longer afraid of receiving Japanese specs."

Decision: ROI clear (comtor productivity), zero security incidents, high user satisfaction → deploy org-wide, approve v2 budget.

Capabilities: KPI tracking, data export for reporting, audit log (security incident proof), pilot → scale pathway.

Data export for pilot reporting (manual export from genie-api logs) is deferred from v1 as a formal product feature — Teddy compiles it manually during the pilot. Automated export UI is a v2 capability.

Journey 6: Office Staff — Report Comprehension​

Persona: Hana — Business Operations, CyberAgent

Hana receives a monthly KPI dashboard link with dense metrics and Japanese annotations. She needs to extract key points for a 10-minute team standup — in 5 minutes.

Opening Scene: Hana opens the KPI report page. Half the commentary is in Japanese. Her current workflow: copy sections into ChatGPT, ask for summary, paste result into notes. Every time she does this, she feels uneasy — "Should I be pasting this data outside?" Today's deadline is tighter than usual.

Rising Action: Hana opens Genie sidebar (Cmd+K), clicks Summarize Page. Genie reads the full dashboard, summarizes in Vietnamese:

  • "3 điểm chính tháng này: [X, Y, Z]. Phần liên quan đến Operations team: [đoạn cụ thể]."

Genie detects Japanese annotations and translates them inline, without Hana having to select anything manually.

Climax: Hana reads the summary in under 30 seconds. All data stayed on the page — nothing was sent to an external tool. She copies the summary into her standup notes.

Resolution: Standup runs on time. No data left CyberAgent's infrastructure. Hana uses Genie for every monthly report from now on — and stops using ChatGPT for work content entirely.

Capabilities: Page summarization, multilingual translation (inline Japanese → Vietnamese), zero data exfiltration (all via genie-api), no page navigation required.
