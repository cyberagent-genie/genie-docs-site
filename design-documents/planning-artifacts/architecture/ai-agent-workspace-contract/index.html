AI Agent Workspace Contract

ADR-009: Standardized AI Agent Workspace Layout​

Status: Accepted
Date: 2026-03-18
Scope: genie-api, genie-chrome-extension, genie-db, genie-bot (all sub-repos)

Context​

The Genie system uses an Autonomous AI Dev Pipeline where AI agents (OpenCode + BMAD) run inside GitHub Actions CI jobs scoped to individual sub-repos (genie-api, genie-chrome-extension, genie-db). BMAD planning artifacts — story files, workflow engine, AI commands, sprint status — all live in the parent genie-system repo, not in the sub-repos.

When an AI agent runs inside a sub-repo CI job, it only has access to:

  • The sub-repo source code
  • Whatever is explicitly checked out alongside it

The BMAD workflow engine resolves paths relative to {project-root} — the working directory of the AI agent process. Without a consistent layout, the engine cannot find:

  • docs/.bmad/ — workflow definitions and config
  • docs/ai-commands/ — OpenCode commands and agents
  • docs/design-documents/implementation-artifacts/ — story files, beads-id-map.yaml, sprint-status.yaml

This creates a gap: AI agents receive a task but cannot load the context needed to implement it correctly.

Decision​

Define a standardized workspace layout (the AI Agent Workspace Contract) that all environments — CI runners and local development — must satisfy before an AI agent is invoked.

The contract is enforced by the setup-ai-workspace GitHub Action (CI) and scripts/setup-ai-workspace.sh script (local dev).

Workspace Layout Contract​

After setup, the workspace of any sub-repo must conform to:

$WORKSPACE_ROOT/                            (sub-repo root)
│
├── docs/
│   ├── .bmad/                              ← BMAD workflow engine    [INJECTED from genie-system]
│   │   └── bmm/
│   │       ├── config.yaml
│   │       └── workflows/
│   ├── ai-commands/                        ← OpenCode commands        [INJECTED from genie-system]
│   │   ├── opencode/
│   │   └── opencode-agents/
│   ├── design-documents/
│   │   └── implementation-artifacts/       ← story files, beads maps  [INJECTED from genie-system]
│   │       ├── beads-id-map.yaml
│   │       ├── sprint-status.yaml
│   │       └── <story-key>.md
│   └── project-context/                    ← coding standards         [LOCAL — never overwritten]
│       └── index.md
│
├── .opencode/
│   ├── commands  → docs/ai-commands/opencode/         (symlink)
│   └── agents   → docs/ai-commands/opencode-agents/  (symlink)
│
├── .genie-system/                          ← raw genie-system clone   [traceability only]
│
└── [sub-repo source code]

Contract Rules​

RuleRationale
docs/project-context/ is never overwrittenEach sub-repo owns its own coding standards
Only implementation-artifacts/ is injected — not all of design-documents/Avoids conflicting with any local docs content
Injected paths use copy, not symlinkConsistent behavior across OS environments; easier to debug
.opencode/commands and .opencode/agents use symlinksOpenCode CLI requires symlinks for command discovery
Injected paths are listed in .gitignorePrevents accidental commits of generated/injected content
Contract is verified before AI agent runsFail fast — loud error vs. silent wrong behavior

Implementation​

CI: setup-ai-workspace Action​

Location: cyberagent-genie/genie-ci-toolkit/actions/setup-ai-workspace

Replaces: checkout-story-context (backward compat wrapper maintained)

# In any sub-repo ai-dev-pipeline.yml:
- uses: cyberagent-genie/genie-ci-toolkit/actions/setup-ai-workspace@latest
  with:
    access_token: ${{ needs.auth.outputs.access_token }}

The action:

  1. Clones genie-system into .genie-system/ (raw, for traceability)
  2. Copies docs/.bmad/, docs/ai-commands/, docs/design-documents/implementation-artifacts/ into workspace docs/
  3. Creates .opencode/ symlinks
  4. Runs a verification step that fails CI if any contract path is missing

Backward Compatibility​

checkout-story-context is now a thin wrapper around setup-ai-workspace. Existing pipeline callers do not need to change. The story_context_dir output is preserved as an alias for workspace_root.

Deprecated inputs removed from opencode-run:

  • opencode_commands_dir — no longer needed; contract guarantees .opencode/commands
  • opencode_agents_dir — no longer needed; contract guarantees .opencode/agents

Local Dev: setup-ai-workspace.sh Script​

Location: genie-system/scripts/setup-ai-workspace.sh

# Run once from each sub-repo root:
cd genie-api && bash ../scripts/setup-ai-workspace.sh
cd genie-chrome-extension && bash ../scripts/setup-ai-workspace.sh
cd genie-db && bash ../scripts/setup-ai-workspace.sh

Re-run anytime to refresh with latest genie-system content (e.g., after pulling new story files).

.gitignore Entries (all sub-repos)​

# AI Agent Workspace Contract (injected by setup-ai-workspace — do not commit)
docs/.bmad/
docs/ai-commands/
docs/design-documents/implementation-artifacts/
.opencode/
.genie-system/

Consequences​

Positive​

  • AI agent can always find BMAD workflow engine, story files, and implementation artifacts regardless of which sub-repo it runs in
  • Single source of truth: genie-system owns all planning content; sub-repos never need to copy or maintain it manually
  • Workspace contract is verifiable — CI fails immediately with a clear error if setup is incomplete, preventing silent hallucinations
  • Local dev experience mirrors CI exactly — same script, same layout
  • docs/project-context/ (sub-repo-specific coding standards) is fully preserved and takes precedence over any genie-system content

Trade-offs​

  • Developers must run setup-ai-workspace.sh once locally before using opencode in sub-repos (one-time setup)
  • implementation-artifacts/ is a point-in-time snapshot at CI trigger time — if story files change in genie-system mid-run, the agent sees the version at checkout (acceptable: story files are immutable once created)
  • cp -rn (no-overwrite) means stale local copies of injected paths persist until re-run — mitigated by re-running script after git pull

Alternatives Considered​

Symlink approach: Create symlinks from sub-repo docs/ into .genie-system/docs/. Rejected because symlinks behave inconsistently across OS environments and are fragile in CI runners with restricted permissions.

Workflow path fix: Update BMAD instructions.xml to use .genie-system/ prefix for all paths. Rejected because BMAD is a shared workflow engine — patching internal path references tightly couples the engine to the CI layout rather than defining a clean contract.

Git submodule in sub-repos: Add genie-system as a submodule inside each sub-repo. Rejected because it creates circular dependency (genie-system contains sub-repos as submodules; sub-repos would contain genie-system as a submodule).
