Project Context Analysis

Requirements Overview​

Functional Requirements (45 FRs / 8 nhóm):

  • AI Actions (FR1–6): Translate, Summarize, Next Steps, Chat với model selection → requires abstracted AIProvider interface với streaming support
  • Conversation Context (FR7–9): Session-scoped history (≥10 turns), auto-delete on logout → in-memory or client-side store, no server-side persistence (stateless API)
  • Knowledge Base & Grounding (FR10–15, FR45): RAG over Confluence, confidence scoring, citation, recency indicator → vector store + multilingual embedding pipeline
  • Extension & Interface (FR16–22): Shadow DOM sidebar, SSE streaming UI, offline/error states, onboarding wizard
  • Auth & Access Control (FR23–26, FR42): SSO-mandatory, idle timeout, inline re-auth via popup (no page navigation)
  • Governance & Security (FR27–34, FR43–44): All AI via genie-api proxy, model allowlist enforcement per-request, per-user rate limit (10 req/min), audit log (metadata only — no content, no PII)
  • Analytics & Feedback (FR35–38): Session events, weekly return cohorts, NPS survey, inline accept/reject feedback
  • Operations (FR39–41): Health check endpoint, semantic versioning contract extension↔genie-api, backward compat guarantee

Scale & Complexity:

  • Primary domain: Full-stack — Chrome Extension (MV3) + Go backend + Vector DB + LLM Gateway
  • Complexity level: Medium-High (SSO, RAG pipeline, streaming, Shadow DOM, Chrome security model)
  • Pilot: 4 concurrent users → no immediate scale pressure, but stateless architecture required from day 1
  • Estimated architectural components: ~14 units

Technical Constraints & Dependencies​

Already decided (existing project context):

  • genie-api: Go 1.23 + Gin + Clean Architecture; AIProvider interface already defined
  • Extension: MV3, React + TypeScript strict, Shadow DOM, pnpm, React Context only (no Redux/Zustand)
  • DB: MySQL 8.0 + Prisma Client Go
  • Auth: JWT now → SSO later (swappable middleware pattern planned)
  • Planned: Redis (cache layer, interface abstraction), S3 (StorageProvider interface)

Communication model (from PRD):

content_script ←→ background service_worker ←→ genie-api ←→ LLM Provider
                                                    ↕
                                              Confluence Index (Vector Store)

Cross-Cutting Concerns Identified​

  1. SSO Authentication — genie-api auth middleware + service worker token management (in-memory) + inline re-auth UX (popup, no page navigation) + auto-retry pending action after re-auth
  2. Streaming Pipeline — structured SSE protocol: metadata event (confidence + sources) FIRST → chunk events (text) → done event; port-based messaging in extension (chrome.runtime.connect) required for streaming — sendMessage is one-shot only
  3. RAG/Confidence — Confluence vector search must complete BEFORE stream begins (confidence block renders first per UX spec); requires Confluence query timeout strategy — on timeout, fallback to LLM-only with explicit low-confidence signal
  4. Rate Limiting — per-user (10 AI req/min), applied at genie-api middleware, 429 + Retry-After header
  5. Observability — audit logs (metadata only: user, timestamp, action, model, response time — NO content, NO query text), session events, Confluence index status endpoint for IT Admin
  6. Versioning Contract — semantic versioning extension↔genie-api; /v_prev/ rollback endpoint active during grace period
  7. Confluence Permission Model — v1: shared index, uniform pilot permissions (4 comtors); v2: per-user permission filtering at query time — design KnowledgeProvider interface now to avoid v2 refactor
  8. Extension Bundle Budget — 200KB hard limit drives build pipeline decisions: Tailwind JIT, tree-shaking, CSS injection strategy for Shadow DOM
