Core Architectural Decisions

Decision Priority Analysis​

Critical Decisions (Block Implementation):

  • Conversation history storage → Redis server-side
  • Embedding model → multilingual-e5-large self-hosted
  • SSE streaming protocol → structured metadata-first schema
  • Qdrant timeout → 1000ms with fallback

Important Decisions (Shape Architecture):

  • JWT auth → 1h access token + 8h refresh token, auto-refresh
  • IT Admin interface → separate React app (genie-admin), independently deployed
  • Tailwind Shadow DOM → Constructable Stylesheets API
  • Logging → stdout only via log/slog

Deferred Decisions (Post-MVP):

  • SSO implementation (JWT now, SSO later — swappable middleware)
  • Per-user Confluence permission filtering (v2)
  • Multi-source KnowledgeProvider (v2)

Data Architecture​

Conversation History Storage

  • Decision: Redis server-side, TTL = SSO session lifetime (8h)
  • Key: session ID (not user ID — per-session scoped)
  • Encrypted at rest (NFR-S2)
  • Auto-expire on session end, manual clear on logout
  • Affects: genie-api session middleware, Redis Docker service

Embedding Model

  • Decision: intfloat/multilingual-e5-large via HuggingFace Text Embeddings Inference (TEI)
  • Deployment: self-hosted Docker container (port 8000)
  • Rationale: JP/VI/EN multilingual quality, data never leaves CyberAgent infrastructure, zero per-call cost
  • Docker image: ghcr.io/huggingface/text-embeddings-inference:cpu-latest
  • RAM requirement: ~2GB
  • Embedding happens at index time (daily sync) — not user-facing latency path

Primary Database

  • Decision: MySQL 8.0 (already established) — stores users, sessions, model allowlist, Confluence space config, audit log metadata
  • Migration: Prisma schema as source of truth

Authentication & Security​

SSO via CyberAgent OIDC + K8s Ingress Auth

CyberAgent đã có OIDC provider — genie tích hợp theo pattern ingress auth_request (giống k8s OIDC webhook). genie-api không tự validate token — ingress handles validation.

[Chrome Extension]
    ↓  Authorization Code + PKCE → CyberAgent OIDC Provider
    ←  opaque access token
    ↓  Bearer: <opaque_token>
[K8s Ingress — nginx + oauth2-proxy]
    →  validate token với OIDC introspection endpoint
    →  valid:   forward + inject headers → genie-api
                  X-Auth-User: teddy@cyberagent.co.jp
                  X-Auth-Email: teddy@cyberagent.co.jp
                  X-Auth-Groups: engineering,genie-pilot
    →  invalid: 403 tại ingress — không đến genie-api
[genie-api]
    →  auth_middleware đọc X-Auth-User / X-Auth-Groups
    →  KHÔNG validate token — trust headers (internal network)

Extension OIDC Flow (Authorization Code + PKCE):

  • chrome.identity.launchWebAuthFlow() → CyberAgent OIDC login page
  • Code exchange qua POST /api/v1/auth/token (genie-api proxy — tránh CORS, giấu client_secret)
  • Opaque token lưu in-memory trong service worker
  • Token refresh: re-run PKCE flow khi token expire (silent nếu OIDC session còn; interactive nếu hết)
  • Re-auth trigger: AuthBanner khi token expire và silent refresh fail

auth_middleware.go implementation:

func AuthMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        userEmail := c.GetHeader("X-Auth-User")
        if userEmail == "" {
            // Local dev fallback via GENIE_DEV_USER env var
            userEmail = os.Getenv("GENIE_DEV_USER")
            if userEmail == "" {
                c.AbortWithStatusJSON(403, gin.H{"error": "AUTH_MISSING", "message": "Unauthorized"})
                return
            }
        }
        groups := c.GetHeader("X-Auth-Groups")
        c.Set("user_email", userEmail)
        c.Set("user_groups", groups)
        c.Set("is_admin", strings.Contains(groups, "genie-admin"))
        c.Next()
    }
}

Admin role: check X-Auth-Groups contains genie-admin — không cần JWT claim riêng.

Local dev (docker-compose — không có k8s ingress):

  • Set GENIE_DEV_USER + GENIE_DEV_GROUPS trong .env
  • Middleware fallback tự động dùng khi X-Auth-User header absent
  • ⚠️ GENIE_DEV_* vars KHÔNG được set trên staging/production

IT Admin Interface

  • Decision: Separate React app (genie-admin submodule), independently deployed
  • Tech stack: React + TypeScript + Vite + pnpm + Tailwind (same pattern as genie-chrome-extension)
  • Hosting: separate deployment (v1: Vite build served from any static host)
  • CORS: genie-api whitelist admin domain in CORS middleware
  • Auth: same OIDC flow, admin access controlled by genie-admin group membership in OIDC provider
  • Pages: Index Status, Model Allowlist, Confluence Spaces Config, Log Viewer

API & Communication Patterns​

SSE Streaming Protocol

All AI action endpoints return Server-Sent Events with this exact schema:

// Event 1: ALWAYS first — before any content streams
{ type: "metadata", confidence: 0.85, confidenceLevel: "high" | "medium" | "low" | "none", sources: [{ title: string, url: string, lastUpdated: string }], sourceCount: number }

// Events 2..N: content chunks
{ type: "chunk", text: string }

// Final event
{ type: "done", totalTokens?: number }

// On error
{ type: "error", code: string, message: string }
  • Go implementation: http.Flusher interface in Gin handler
  • Extension consumption: chrome.runtime.connect() port — NOT sendMessage
  • Confidence levels: high ≥ 0.7, medium ≥ 0.4, low ≥ 0.1, none = 0 or timeout

Confluence Query Timeout & Fallback

  • Qdrant query timeout: 1000ms (aligns with NFR-P4)
  • On timeout: proceed with LLM-only, send metadata event with confidenceLevel: "none", sourceCount: 0
  • On Confluence index unavailable: same fallback — LLM-only with explicit warning
  • Timeout set via context.WithTimeout(ctx, time.Second) in KnowledgeProvider implementation

REST API

  • All routes: /api/v1/ (established)
  • Admin routes: /api/v1/admin/ — require is_admin: true (từ X-Auth-Groups header, set bởi auth_middleware)
  • Error format: established (error, message, details, timestamp)
  • Rate limit: 10 AI req/min per user → 429 + Retry-After header

Frontend Architecture​

Tailwind CSS Shadow DOM Injection

  • Decision: Constructable Stylesheets API
  • Implementation: 
    // content-script/index.tsx
    const sheet = new CSSStyleSheet();
    sheet.replaceSync(tailwindCSS); // imported as string via Vite ?inline
    shadowRoot.adoptedStyleSheets = [sheet];
  • Vite config: import CSS with ?inline suffix to get string
  • Tailwind: JIT mode, purge unused classes — must stay within 200KB bundle budget

Extension Streaming Transport

  • Decision: chrome.runtime.connect() port-based messaging for all AI action responses
  • chrome.runtime.sendMessage reserved for non-streaming messages only (auth, settings)
  • Port name convention: "genie-stream-${actionId}"

Infrastructure & Deployment​

Logging Strategy

  • Decision: stdout only via log/slog (structured JSON)
  • IT Admin access: docker logs genie-api
  • Audit log metadata written to MySQL (queryable via admin UI) — content never logged
  • Log retention: 30 days (Docker log rotation config)

Decision Impact Analysis​

Implementation Sequence (order matters):

  1. Add Redis + Qdrant + embedding-server to docker-compose.yml
  2. Define KnowledgeProvider interface in genie-api usecase layer
  3. Implement Confluence indexing + TEI embedding pipeline
  4. Validate RAG quality on real Confluence pages (before building extension UI)
  5. Implement JWT auth middleware (access + refresh token flow)
  6. Implement SSE streaming handler with metadata-first protocol
  7. Implement extension service worker with port-based streaming
  8. Build extension React UI (confidence block, streaming response, citation chips)
  9. Build genie-admin React app
  10. Implement rate limiting, audit logging, admin endpoints

Cross-Component Dependencies:

  • KnowledgeProvider interface must exist before any RAG feature story starts
  • SSE schema must be agreed before genie-api and extension are implemented in parallel
  • JWT auth must be working before any protected endpoint can be tested
  • Embedding server must be running before Confluence sync can be tested
  • genie-admin CORS config in genie-api must be set before admin app can talk to API
