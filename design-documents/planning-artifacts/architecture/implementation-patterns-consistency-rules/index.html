Implementation Patterns & Consistency Rules

9 conflict areas identified. All patterns below are mandatory for all AI agents.

P1: Database Naming (MySQL via Prisma)​

RuleExample
Table names: snake_case, pluralusers, audit_logs, confluence_spaces
Column names: snake_caseuser_id, created_at, refresh_token
Foreign keys: <table_singular>_iduser_id, space_id
Index names: idx_<table>_<column>idx_users_email, idx_sessions_user_id
Prisma model names: PascalCase (auto-maps → snake_case table)model User, model AuditLog
Migration file naming: YYYYMMDDHHMMSS_<description>.sql20260316090000_create_users_table.sql

P2: API Endpoint Naming​

RuleExample
All plural, kebab-case/api/v1/users, /api/v1/confluence-spaces
Route params: :id/api/v1/users/:id
Query params: snake_case?page=1&per_page=20
Admin prefix/api/v1/admin/index-status

P3: Go Code Naming​

RuleExample
Exported: PascalCaseUserUsecase, KnowledgeProvider
Unexported: camelCaseuserRepo, buildResponse
Interface names: no I prefixAIProvider, KnowledgeProvider
Error wrapping: "Package.Method: %w""UserUsecase.Create: %w"
Test files: co-located, suffix _test.gouser_usecase_test.go
Mock files: mocks/ subdir adjacent to interfaceinternal/usecase/mocks/MockAIProvider.go

P4: TypeScript/Extension Code Naming​

RuleExample
Component files: PascalCase.tsxConfidenceBlock.tsx, ChatInput.tsx
Hook files: camelCase.ts, prefix useuseStreamingResponse.ts
Utility/service files: camelCase.tsstorageService.ts, messageHandler.ts
Imports: always @/ alias, never relative ../../import { useAuth } from '@/features/auth'
Types/Interfaces: PascalCase, no I prefixStreamMetadata, ConversationTurn
Enums/constants: const object + derived typeMessageType.START_STREAM

P5: API Response Format (LOCKED)​

JSON field naming: camelCase trong response data (Go struct tags: json:"userId") Date/time: ISO 8601 strings — never Unix timestamps Booleans: true/false — never 1/0 Null: omit field using omitempty where possible

// Success
{ "data": {}, "message": "optional", "timestamp": "2026-03-16T09:00:00Z" }

// Error
{ "error": "AUTH_INVALID_TOKEN", "message": "Human-readable", "details": {}, "timestamp": "..." }

// Pagination
{ "data": [], "pagination": { "page": 1, "limit": 20, "total": 100, "hasMore": true }, "timestamp": "..." }

P6: SSE Event Schema (LOCKED)​

Event order: metadata ALWAYS first, then chunk events, then done.

{ type: "metadata", confidence: 0.85, confidenceLevel: "high"|"medium"|"low"|"none", sources: [...], sourceCount: number }
{ type: "chunk", text: string }
{ type: "done", totalTokens?: number }
{ type: "error", code: string, message: string }
  • Go: write data: <json>\n\n via http.Flusher
  • Extension: consume via chrome.runtime.connect() port, name convention "genie-stream-${actionId}"

P7: Redis Key Format​

genie:conversation:{session_id}
  • Namespace prefix genie: mandatory — prevents collision if Redis is shared post-pilot
  • Key scope: per-session (not per-user)
  • TTL = 8h (refresh token lifetime)

P8: Error Handling Patterns​

genie-api:

  • Usecase layer: return *AppError — never raw error for user-facing errors
  • Handler layer: errors.As(err, &appErr) → convert to JSON response
  • Always wrap: fmt.Errorf("UseCase.Method: %w", err)
  • Never log user query content or response content — log error type + timestamp only

Chrome Extension:

  • Component: never handle errors directly — delegate to hook
  • Hook: catch → set error state → return to component
  • Stream errors: type: "error" event → close port → show inline error in UI

P9: Clean Architecture Boundaries (genie-api)​

handler/ → usecase/ → repository/ → entity/
  • handler: bind input + call usecase + serialize output only. No business logic.
  • usecase: all business logic. No gin, no net/http imports. No direct DB calls.
  • repository: data access via Prisma only. No business rules.
  • entity: pure data structs. No methods with business logic.
  • AI calls: only via AIProvider interface injected into usecase
  • Knowledge calls: only via KnowledgeProvider interface injected into usecase

P10: State Management (Extension)​

  • React Context only — no Redux, no Zustand
  • Context naming: <Domain>Context.tsx — AuthContext.tsx, StreamContext.tsx
  • One context per domain — no merging unrelated state
  • Loading states: per-action boolean local to hook — isTranslating, isSummarizing
  • Global state: auth status only → AuthContext
  • Conversation history: ConversationContext, in-memory array, cleared on session end

P11: Logging (genie-api)​

// ✅ Always structured slog
slog.Info("request completed", "user_id", userID, "action", "translate", "duration_ms", elapsed)
slog.Error("provider failed", "error", err, "provider", "openai")

// ❌ NEVER log
// - User query content or response content
// - JWT tokens or credentials
// - Any PII

P12: Chrome Extension Message Constants​

Define in src/shared/types/messages.ts — no string literals inline:

export const MessageType = {
  START_STREAM:     'START_STREAM',
  GET_AUTH_STATUS:  'GET_AUTH_STATUS',
  CLEAR_SESSION:    'CLEAR_SESSION',
} as const;
export type MessageType = typeof MessageType[keyof typeof MessageType];

Port name convention for streaming: "genie-stream-${actionId}"

P13: Environment Variable Naming​

  • Custom vars: prefix GENIE_ — GENIE_OIDC_ISSUER, GENIE_OPENAI_API_KEY, GENIE_QDRANT_URL
  • Standard infra vars: no prefix — MYSQL_HOST, REDIS_URL
  • Never hardcode — always load from env via typed config struct in cmd/api/main.go

P14: Test Structure​

Go — table-driven (mandatory):

testCases := []struct {
    name     string
    input    SomeInput
    wantErr  bool
    wantData SomeOutput
}{
    {name: "success case", ...},
    {name: "error case", ...},
}
for _, tc := range testCases {
    t.Run(tc.name, func(t *testing.T) { ... })
}

TypeScript — describe/it (mandatory):

describe('ComponentName', () => {
    it('should handle success case', () => { ... });
    it('should handle error state', () => { ... });
});
// Mocks: vi.fn() via Vitest

P15: Feature-Sliced Design (FSD) — Extension Frontend Structure​

FSD applied inside src/. Chrome Extension entry points (content-script/, service-worker/) remain at MV3-required locations outside FSD layers.

Layer hierarchy (imports flow top → bottom only — never reverse):

src/
├── content-script/         # MV3 entry — mounts App into Shadow DOM
├── service-worker/         # MV3 entry — handles all messages, calls genie-api
│
├── app/                    # App layer — providers, root context wiring
│   ├── providers/          # AuthProvider, StreamProvider
│   └── App.tsx
│
├── pages/                  # Pages layer — top-level view compositions
│   ├── SidebarPage.tsx
│   └── OnboardingPage.tsx
│
├── widgets/                # Widgets layer — self-contained UI blocks
│   ├── ConfidenceBlock/
│   ├── ActionToolbar/
│   └── ConversationPanel/
│
├── features/               # Features layer — user-facing action slices
│   ├── translate/
│   │   ├── ui/             # TranslateButton.tsx, TranslateResult.tsx
│   │   ├── model/          # useTranslate.ts
│   │   └── index.ts        # Public API — only import from here
│   ├── summarize/
│   ├── next-steps/
│   ├── chat/
│   └── auth/
│
├── entities/               # Entities layer — domain objects & their UI
│   ├── user/
│   ├── message/
│   └── knowledge-source/
│
└── shared/                 # Shared layer — zero business logic
    ├── ui/                 # Button, Input, Spinner, ErrorBanner
    ├── lib/                # storageService.ts, apiClient.ts, messageHandler.ts
    ├── types/              # messages.ts, shared TS interfaces
    ├── config/             # constants, env vars
    └── styles/             # Tailwind globals

Import rules:

LayerCan import from
apppages, widgets, features, entities, shared
pageswidgets, features, entities, shared
widgetsfeatures, entities, shared
featuresentities, shared
entitiesshared
sharedNothing — zero upward imports

Slice public API rule:

// ✅ Correct — import from slice index
import { TranslateButton } from '@/features/translate';

// ❌ Forbidden — deep import violates slice encapsulation
import { TranslateButton } from '@/features/translate/ui/TranslateButton';

Migration map from current structure:

CurrentFSD destination
components/common/shared/ui/
components/features/features/<name>/ui/
components/layout/widgets/
hooks/features/<name>/model/ or shared/lib/
services/shared/lib/
utils/shared/lib/
types/shared/types/
styles/shared/styles/

Enforcement — All AI Agents MUST​

  • Read genie-api/docs/project-context/ before implementing any Go feature
  • Read genie-chrome-extension/docs/project-context/ before implementing any extension feature
  • Never import gin/net/http into usecase layer
  • Never use any type in TypeScript — use unknown + narrow explicitly
  • Never call chrome.storage directly in components — always via storageService.ts
  • Never use relative imports ../../ — always use @/ path alias
  • Never hardcode credentials — always load from env
  • Always use pnpm — never npm or yarn
  • Always write tests co-located with implementation (_test.go / .test.ts)
  • Always import from slice index.ts — never deep-import into feature internals
  • Always use GENIE_ prefix for custom env vars
