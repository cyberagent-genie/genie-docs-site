CI/CD Pipeline Strategy

ADR-008: CI/CD Pipeline — Hybrid SHA Staging + Tag Production​

Pattern: merge to main → staging auto-deploy (SHA-tagged image); git tag → production deploy (semver-tagged image) Registry: CyberAgent internal registry (registry.cyberagent.internal) Runtime: Kubernetes — namespaces genie-staging / genie-production Runner: genie-bot self-hosted GitHub Actions runner

genie-api Pipeline​

PR opened
  → golangci-lint
  → go test ./...
  → build check

PR merged to main
  → build Docker image
  → push registry.cyberagent.internal/genie/api:sha-<commit_sha>
  → kubectl set image deployment/genie-api → genie-staging namespace
  → health check: GET /api/v1/health → assert status "ok"

git tag v1.2.0
  → re-tag sha-<commit_sha> → v1.2.0
  → trigger genie-db migrate deploy (must succeed before app deploy)
  → kubectl set image deployment/genie-api → genie-production namespace
  → health check → if fail: kubectl rollout undo deployment/genie-api

Deploy order on production: genie-db migrate deploy → genie-api rolling update Ensures DB schema is ready before new app version starts serving traffic.

genie-db Pipeline​

PR opened
  → prisma format --check (schema lint)
  → prisma migrate diff (dry-run — detect drift)
  → PR template checklist:
      [ ] Does this migration DROP or RENAME? → Must be Phase 3 of Expand/Contract
      [ ] Phase 1 (Expand) already deployed and verified?

PR merged to main
  → go run prisma-client-go generate (regenerate ./prisma/db/)
  → commit generated client files
  → auto-bump patch version tag (v0.x.y → v0.x.y+1)

Manual tag v0.X.0 (minor/major)
  → triggers genie-api production deploy pipeline
  → migrate deploy runs first (see genie-api pipeline above)

genie-chrome-extension Pipeline​

PR opened
  → pnpm tsc --noEmit (TypeScript strict check)
  → pnpm lint (ESLint)
  → pnpm test (Vitest)
  → pnpm build → bundle size check: assert dist/ < 200KB

PR merged to main
  → pnpm build (production bundle)
  → package → dist-sha-<commit_sha>.zip
  → upload as GitHub Releases draft artifact (staging artifact for QA)

git tag v1.2.0
  → pnpm build (production bundle)
  → package → genie-extension-v1.2.0.zip
  → publish GitHub Release (release notes auto-generated)
  → IT Admin downloads .zip → sideload via chrome://extensions (pilot)
  → [Post-pilot] upload to Chrome Enterprise Policy via Google Admin Console

Bundle size enforcement: CI fails if dist/ exceeds 200KB — enforces NFR-P5.

genie-admin Pipeline​

PR merged to main
  → lint + tsc + test
  → build → push registry.cyberagent.internal/genie/admin:sha-<commit_sha>
  → kubectl set image → genie-staging namespace

git tag v1.2.0
  → re-tag → v1.2.0
  → kubectl set image → genie-production namespace

(Same pattern as genie-api — no migration dependency)

genie-db Pipeline (separate from genie-api)​

genie-db migrations run independently before genie-api deploy:

  • Staging: auto-run on merge to main (safe — Expand/Contract ensures backward compat)
  • Production: explicit step in genie-api production pipeline, must succeed before rolling update

Rollback Strategy​

ScenarioAction
genie-api bad deploykubectl rollout undo deployment/genie-api → previous SHA image
genie-db bad migrationExpand/Contract — data intact in old column; revert genie-api to previous version
Extension bad versionIT Admin sideloads previous .zip from GitHub Releases
Qdrant collection corruptSet GENIE_QDRANT_COLLECTION=genie_confluence_v{prev} → redeploy genie-api
genie-admin bad deploykubectl rollout undo deployment/genie-admin
