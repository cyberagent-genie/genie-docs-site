Architecture Validation Results

Coherence Validation ✅​

All technology choices compatible. No version conflicts. Patterns align with stack decisions. Clean Architecture (Go) and FSD (TypeScript) enforce separation of concerns consistently without contradiction. genie- prefix naming consistent across all 5 services.

Gap Analysis — All Resolved​

G1 (Critical): genie-api env vars​

All genie-api environment variables documented. Agents MUST load from env — never hardcode:

# OIDC / SSO (server-side only — never expose to extension)
GENIE_OIDC_ISSUER=https://sso.cyberagent.co.jp
GENIE_OIDC_CLIENT_ID=genie-app
GENIE_OIDC_CLIENT_SECRET=

# Local dev auth fallback (NOT set on staging/production)
GENIE_DEV_USER=teddy@cyberagent.co.jp
GENIE_DEV_GROUPS=engineering,genie-pilot

# AI Provider
GENIE_OPENAI_API_KEY=

# Infrastructure (Docker internal DNS)
GENIE_QDRANT_URL=http://local-qdrant.genie.local:6333
GENIE_QDRANT_COLLECTION=genie_confluence_v1
GENIE_EMBEDDING_URL=http://local-embedding.genie.local:8000
GENIE_REDIS_URL=redis://:password@local-redis.genie.local:6379

# Confluence
GENIE_CONFLUENCE_BASE_URL=
GENIE_CONFLUENCE_API_TOKEN=        # service account token — NOT personal token (see V-B)

# MySQL (standard vars — no GENIE_ prefix)
MYSQL_HOST=local-mysql.genie.local
MYSQL_PORT=3306
MYSQL_DATABASE=local_genie
MYSQL_USER=user
MYSQL_PASSWORD=

G2 (Important): Rate limit — atomic Redis pattern​

  • Key: genie:ratelimit:{user_id}, TTL 60s
  • Implementation: atomic SET key 1 EX 60 NX + INCR pattern — NOT two separate INCR + EXPIRE calls (race condition risk)
  • Fail open: if genie-redis unavailable → allow request, log warning slog.Warn("rate limit unavailable, failing open")
  • IP-based rate limit: apply to /api/v1/auth/* endpoints only (unauthenticated)

G3 (Important): Confluence API credentials​

  • GENIE_CONFLUENCE_API_TOKEN MUST be a service account token — not a personal developer token
  • IT Admin creates dedicated Confluence bot account, generates API token for it
  • Personal tokens expire when employee leaves → indexer breaks silently

Security Validation — Red Team Findings​

RT-1: JWT client fingerprint binding​

JWT claims include client_fingerprint: SHA256(user-agent + ip) validated in auth_middleware.go. Stolen token unusable from different client.

RT-2: Rate limiting scope​

Rate limit per user_id via JWT — sufficient for SSO-only access model (no open registration). IP rate limit applies to /api/v1/auth/* only.

RT-3: Confluence index access warning​

⚠️ V1 SECURITY NOTE: Shared Confluence index assumes all pilot users have equivalent Confluence access. Do NOT index spaces with restricted access (HR, Finance, exec-only) until v2 per-user permission filtering is implemented.

RT-4: XSS prevention in streaming components​

dangerouslySetInnerHTML is forbidden in all streaming/AI response components. React default text rendering escapes HTML. If markdown rendering needed: use react-markdown + rehype-sanitize only.

RT-5: Audit log timing​

Audit log write happens before stream begins (not after). Schema: {user_id, action, model, timestamp, request_id}. Ensures audit record exists even if genie-api crashes mid-stream.

Pre-mortem Prevention Items​

PM-1: RAG stale data — user trust​

metadata SSE event includes indexLastUpdated: string (ISO 8601). Extension UI displays "Nguồn được index lúc..." timestamp. Source chips show individual page lastUpdated.

PM-2: Corporate proxy SSE buffering​

genie-api SSE responses MUST include:

X-Accel-Buffering: no
Cache-Control: no-cache
Connection: keep-alive
Content-Type: text/event-stream

PM-3: Dependency health visibility​

GET /api/v1/health returns dependency status for IT Admin monitoring:

{
  "status": "ok|degraded|down",
  "services": {
    "genie-mysql": "ok",
    "genie-redis": "ok",
    "genie-qdrant": "ok",
    "genie-embedding": "ok|degraded",
    "confluence-index": { "status": "ok|stale", "lastSync": "2026-03-16T02:00:00Z" }
  }
}

PM-4: MySQL connection pool​

Set in main.go when initializing Prisma client:

db.SetMaxOpenConns(10)
db.SetMaxIdleConns(5)
db.SetConnMaxLifetime(5 * time.Minute)

PM-5: Extension version negotiation​

Service worker handles version mismatch: if received message version > current handler version → send { type: "error", code: "VERSION_MISMATCH" } → UI triggers chrome.runtime.reload().

Failure Mode Mitigations​

FM-1: gin.Recovery() middleware​

gin.Recovery() MUST be mounted explicitly in router setup in main.go — prevents unhandled panics from crashing service.

FM-2: Prisma query timeout​

Prisma client initialized with query timeout: 10s. Set via connection string param or middleware.

FM-3: Redis encryption (NFR-S2)​

GENIE_REDIS_URL includes password: redis://:password@local-redis.genie.local:6379. genie-redis Docker service configured with command: redis-server --requirepass ${REDIS_PASSWORD}.

FM-4: Pin Docker image versions​

All Docker images MUST be pinned to specific versions — never use latest:

genie-qdrant:   qdrant/qdrant:v1.9.0
genie-embedding: ghcr.io/huggingface/text-embeddings-inference:cpu-1.5.0
genie-redis:    redis:7.2-alpine
genie-mysql:    mysql:8.0.36

FM-5: genie-embedding resource constraints​

genie-embedding:
  mem_limit: 3g
  # First-run note: Docker will download multilingual-e5-large model (~1.2GB) on first start.
  # Allow 5-10 minutes for initial startup. Subsequent starts are instant (model cached in volume).

embedding_client.go HTTP client timeout: 30s per batch request.

FM-6: MV3 service worker keepAlive during streaming​

// service-worker/index.ts
function startKeepAlive(): () => void {
  const interval = setInterval(
    () => chrome.runtime.getPlatformInfo(() => {}),
    20_000
  );
  return () => clearInterval(interval);
}
// Call startKeepAlive() when stream begins, call returned cleanup fn on done/error

port.onDisconnect → dispatch error event → content script shows ErrorBanner with retry.

Self-Consistency Findings​

SC-1: Concurrent RAG + LLM execution (NFR-P1 compliance)​

Qdrant query and LLM stream request fire concurrently in handler — NOT sequentially:

// handler: fire both concurrently
go func() { qdrantResult <- knowledgeProvider.Search(ctx, query, 5) }()
go func() { llmStream <- aiProvider.Stream(ctx, prompt) }()

// Wait for Qdrant result (or timeout) → send metadata event → relay LLM chunks

This ensures first token = max(qdrant_time, llm_first_token_time) not sum.

SC-2: service-worker import scope restriction​

service-worker/ entry point may only import from shared/ layer:

  • ✅ shared/lib/ — storageService, messageHandler, apiClient
  • ✅ shared/types/ — MessageType, SSE event types
  • ❌ Forbidden: features/, entities/, widgets/, pages/, app/

Architecture Decision Records​

ADR-006: Database Schema as Separate Repo (genie-db)​

Decision: Database schema and migrations live in cyberagent-genie/genie-db — a separate repo from genie-api. genie-api imports generated Prisma Client Go as a Go module: github.com/cyberagent-genie/genie-db. Rationale: Schema changes can be deployed independently without coupling to application release cycle. IT Admin or DBA can run migrations without genie-api deployment. Prisma client is generated once in genie-db and published via Go module versioning — all consumers stay in sync via go get. Workflow:

  1. Edit genie-db/prisma/schema.prisma
  2. Run ./scripts/migrate.sh dev --name <description> → generates SQL in migrations/
  3. Run ./scripts/generate.sh → regenerates prisma/db/ client
  4. Commit + tag (v0.x.0) + push
  5. genie-api: go get github.com/cyberagent-genie/genie-db@v0.x.0 Trade-offs: +Independent deploy +Single source of truth +DBA-friendly vs -Extra repo to maintain; -genie-api must update go.mod on schema changes. Import in genie-api: import "github.com/cyberagent-genie/genie-db/prisma/db"

ADR-005: SSO via CyberAgent OIDC + K8s Ingress Auth​

Decision: Use CyberAgent OIDC provider via k8s ingress auth_request pattern (oauth2-proxy). genie-api reads X-Auth-User / X-Auth-Groups headers — does NOT self-validate tokens. Extension uses Authorization Code + PKCE via chrome.identity.launchWebAuthFlow(). Rationale: SSO infrastructure already exists — no duplication. Ingress handles all token validation complexity. genie-api stays simple. Standard OIDC PKCE flow is secure for Chrome Extension (MV3). Trade-offs: +Simplicity +Reuse existing infra +No JWT secret management vs -Local dev needs mock headers; -genie-api must trust internal network (never expose port 3000 publicly without ingress). Local dev mitigation: GENIE_DEV_USER env var fallback in auth_middleware.go, clearly documented, inactive on k8s (ingress always injects X-Auth-User).

ADR-001: Self-Hosted Embedding (multilingual-e5-large via TEI)​

Decision: Self-hosted over OpenAI text-embedding-ada-002. Rationale: JP/VI multilingual quality critical; data sovereignty non-negotiable; zero per-call cost. Trade-offs: +Quality +Privacy +Cost vs -RAM overhead -First-run complexity. Mitigation: mem_limit: 3g, health check, first-run documentation.

ADR-002: Redis Server-side Conversation History​

Decision: Redis over client-side extension memory or MySQL. Rationale: NFR-SC3 stateless API; service worker termination risk; NFR-S2 encryption. Trade-offs: +Persistence +Encryption +TTL vs -Additional infra dependency. Mitigation: Fail open on Redis unavailable (history reset, AI still works).

ADR-003: genie-admin as Separate Submodule​

Decision: Separate cyberagent-genie/genie-admin repo over embedded in extension or API-only. Rationale: Independent deploy cycles; 200KB bundle budget protection; separation of concerns. Trade-offs: +Independence +Clean separation vs -4th submodule to maintain. Mitigation: Same tech stack as extension — minimal additional learning curve.

ADR-004: chrome.runtime.connect() Port-based Streaming​

Decision: Port-based over WebSocket or sendMessage polling. Rationale: Chrome-native, no external server, MV3 compatible, bidirectional. Trade-offs: +Native +No infra vs -Service worker termination risk. Mitigation: keepAlive ping every 20s during stream; onDisconnect → ErrorBanner + retry.
