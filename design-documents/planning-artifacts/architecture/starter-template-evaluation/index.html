Starter Template Evaluation

Primary Technology Domain​

Multi-service full-stack — project gồm hai codebases đã được khởi tạo riêng biệt, cộng thêm một infrastructure service mới cần thêm vào:

  • genie-api: Go backend service (already scaffolded)
  • genie-chrome-extension: Chrome Extension frontend (already scaffolded)
  • qdrant: Vector database service (new — to be added to Docker Compose)

Starter Options Considered​

Không applicable cho genie-api và genie-chrome-extension — cả hai đã được khởi tạo trước workflow này. Architectural decisions đã được made tại thời điểm scaffold. Qdrant được selected là vector store mới cần thêm vào stack.

genie-api — Established Foundation​

Initialization: Manual scaffold theo Clean Architecture pattern (không dùng boilerplate generator)

Architectural Decisions Already Made:

  • Language & Runtime: Go 1.23 — stdlib slices, maps, range-over-func
  • HTTP Framework: Gin (github.com/gin-gonic/gin)
  • ORM: Prisma Client Go (github.com/steebchen/prisma-client-go)
  • Database: MySQL 8.0 (local: local_genie)
  • Testing: testify/assert + mockery (mock generation)
  • Linter: golangci-lint (CI enforced)
  • Hot-reload: Air (inside Docker)
  • Logging: log/slog (structured JSON)
  • Config: godotenv + typed Config struct
  • Validation: go-playground/validator v10
  • Architecture Pattern: Clean Architecture (handler → usecase → repository → entity)
  • Dependency Injection: Constructor injection only; wired in cmd/api/main.go
  • AI Provider Abstraction: AIProvider interface defined in internal/usecase/provider.go

Confluence Sync Strategy (v1):

  • Background goroutine + cron scheduler running within genie-api process (không phải separate service)
  • Called via KnowledgeProvider.Sync(ctx) interface method
  • v2 path: extract to separate worker service nếu cần scale

genie-chrome-extension — Established Foundation​

Initialization: Vite + React Chrome Extension template

Architectural Decisions Already Made:

  • Language: TypeScript strict mode (noImplicitAny, strictNullChecks, noUnusedLocals)
  • Framework: React (functional components + hooks only)
  • Build Tool: Vite
  • Package Manager: pnpm (strictly enforced — not npm, not yarn)
  • CSS: Tailwind CSS — bundled via Vite, injected into Shadow DOM root at runtime (NOT loaded from CDN; requires custom Vite config to produce inlined CSS string for Shadow DOM injection)
  • Testing: Vitest + @testing-library/react
  • Linter: ESLint + Prettier
  • Manifest Version: V3 (service worker — not background page)
  • UI Injection Pattern: content-script → Shadow DOM → React app
  • State Management: React Context (no Redux, no Zustand)
  • Persistent Storage: chrome.storage.local via storageService.ts only (never direct)
  • Path Aliases: @/ → src/ (in both vite.config.ts and tsconfig.json)
  • API Communication: All calls proxy through genie-api via service worker (never direct LLM calls)
  • Streaming Transport: chrome.runtime.connect() port-based messaging for streaming (NOT chrome.runtime.sendMessage — one-shot only)

Vector Store — Qdrant (New Infrastructure Component)​

Selected: Qdrant — standalone Docker container

Rationale:

  • No conflict with existing MySQL stack (separate service, separate port)
  • Official Go client available (github.com/qdrant/go-client)
  • REST + gRPC API — easy to abstract behind KnowledgeProvider interface
  • Lightweight Docker image — minimal ops overhead for pilot
  • Production-ready and horizontally scalable for post-pilot growth
  • Pilot scale (4 users, ~1,000 Confluence pages) well within free tier capacity

Docker Compose addition:

qdrant:
  image: qdrant/qdrant:latest
  ports:
    - "6333:6333"
  volumes:
    - qdrant_storage:/qdrant/storage

KnowledgeProvider Interface — Architectural Constraint​

MUST be defined in internal/usecase/ before any RAG implementation:

type KnowledgeProvider interface {
    Search(ctx context.Context, query string, limit int) ([]KnowledgeResult, error)
    Sync(ctx context.Context) error
    IndexStatus(ctx context.Context) (IndexStatus, error)
}
  • Confluence + Qdrant = v1 implementation
  • Multi-source (GitHub docs, Notion) = v2 implementation — zero usecase changes
  • Same pattern as existing AIProvider interface

Note for AI Agents​

Both genie-api and genie-chrome-extension codebases are already initialized — do not re-scaffold or run create commands. All new features are added within the established structure following the patterns above. Qdrant must be added to docker-compose.yml as part of initial RAG setup story.
